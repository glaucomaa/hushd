# MOMENTUM 4: протокол и проверенные факты

Краткая справка по прошивке 3.38.3. Утверждения проверены на наушниках через RFCOMM,
BlueZ и PipeWire. Непроверенные вопросы вынесены отдельно.

## Транспорт

- Управление идёт по Bluetooth Classic + RFCOMM, не по BLE GATT.
- GAIA UUID: `a2129ff3-081b-4c45-8afe-469d9c4842ec`.
- На проверенной прошивке GAIA отвечает на каналах 1 и 15, в том числе одновременно.
- Каналы читаются из SDP; если SDP недоступен, используются 1 и 15.
- Канал 14 использует другой протокол.
- Наушники принимают не больше двух RFCOMM-подключений; третье возвращает `EBUSY`.
- После закрытия сессии перед повторным подключением нужна пауза около 0,5 с.
- GAIA работает параллельно с A2DP и HFP.

## Кадр GAIA v3

```text
FF 03 flags length vendor_hi vendor_lo command_hi command_lo payload...
```

- Обычная команда: `FF 03 00 <len> 04 95 <cmd_hi> <cmd_lo> <payload>`.
- Длина относится только к payload.
- Многобайтовые числа — big-endian.
- Sennheiser vendor: `0x0495`; Qualcomm core: `0x001D`.
- Response: `command | 0x0100`.
- Notification: `command | 0x0080`.
- Error: `command | 0x0180`; первый байт payload — код ошибки.
- Пример запроса заряда: `FF 03 00 00 04 95 06 03`.

Карта команд: [probe/gaia-commands.md](probe/gaia-commands.md).

## Состояние и настройки

- Модель: `0x1206`; прошивка: `0x1201`; HW revision: `0x1200`.
- GAIA API: Qualcomm `0x001D:0x0000`; серийный номер: `0x001D:0x0003`.
- Заряд: `0x0603`; зарядка: `0x0602`.
- ANC: `0x1A01`; прозрачность: `0x1A03`; master switch: `0x1A05`.
- Audio mode: `0x0804`; codec: `0x0800`; sample rate: `0x081A`.
- EQ Gen2: конфигурация `0x1000`, запись полосы `0x1001`, чтение `0x1002`.
- Bass boost: `0x1009` / запись `0x1008`.
- Touch lock: `0x1607` / запись `0x1606`.
- Сопряжённые устройства: список `0x1400` + `0x1401`, свой индекс `0x1407`.
- Подключение хоста: `0x1402 [index]`; отключение: `0x1403 [index]`.
- Текущий статус хоста: `0x1404 [index]`.

## ANC

- Adaptive: `ANC_Status = 1`, затем пара `(3, 1)`.
- Custom: пара `(3, 0)`, затем `ANC_Status = 1`.
- Off: пара `(3, 0)`, затем `ANC_Status = 0`.
- В adaptive и off запись прозрачности игнорируется.
- Перед изменением прозрачности нужно включить custom.
- Диапазон прозрачности: 0 = максимум ANC, 50 = нейтрально, 100 = максимум слышимости.
- Anti-wind: 0 = off, 1 = max, 2 = auto.

## EQ

- На прошивке 3.38.3 используется Gen2, не Gen1.
- Пять полос, диапазон от устройства: −6…+6 дБ, шаг хранения 0,1 дБ.
- UI-метки Sennheiser: 63 / 250 / 1k / 4k / 8k Гц.
- Реальные фильтры из уведомления: 90 / 325 / 1500 / 6500 / 6500 Гц.
- Пресеты хранятся как готовые кривые на стороне клиента.
- Изменения полос слышны только в `AudioMode = 1` (user EQ).
- Neutral — это `AudioMode = 0`, а не обязательно пять нулевых полос.
- Правильный порядок: записать полосы, затем включить нужный audio mode.

## Уведомления

Регистрация: `0x0007 [featureId]`.

- Battery: feature 3; battery `0x0683`, charging `0x0682`.
- Generic audio: feature 4; codec `0x0880`, sample rate `0x089A`, audio mode `0x0884`.
- Device: feature 2; physical state `0x0502`.
- ANC: feature 13; pairs `0x1A81`, transparency `0x1A83`, status `0x1A85`.
- EQ: feature 8; gains `0x1082`.
- Device management: feature 10; paired status `0x1484`.

После регистрации наушники сразу присылают текущие значения свойств.

## Аудио в Linux

- Проверенные профили: A2DP SBC, SBC-XQ, AAC, aptX, aptX HD; HFP CVSD и mSBC.
- aptX HD работает в 24 бит / 48 кГц.
- aptX Adaptive и 96 кГц недоступны в проверенной конфигурации PipeWire.
- GAIA codec `0x0800` возвращает `0xFF`, а sample rate 0 в простое.
- Поэтому профиль, кодек и частоту нужно брать из PipeWire, а не только из GAIA.
- HFP включается для микрофона и снижает качество музыки; обратно помогает профиль `a2dp-sink`.

## Ошибки и особенности

- `0x01`: команда не поддерживается.
- `0x05`: неподдерживаемое свойство или неверный параметр.
- `0x06`: операция невозможна в текущем состоянии (`INCORRECT_STATE`).
- `0x80`: значение уже установлено; обрабатывать как успех.
- Ответы и ошибки могут дублироваться: stale-кадры нужно отбрасывать.
- Индексы сопряжённых устройств могут меняться; свой индекс читаем через `0x1407`.
- `MaxBTConnections` на проверенном экземпляре возвращает 1, хотя мануал разрешает два
  активных подключения. Точный смысл свойства не подтверждён.

## Не проверено

- Формат записи rename и multipoint on/off.
- Назначение протокола на канале 14.
- Точный алгоритм checksum; в проверенном трафике флаг не использовался.
- Поведение всех функций на прошивках, отличных от 3.38.3.

## Запрещённые операции

Не отправлять factory reset (`0x0040`), очистку сопряжений (`0x1406`), DFU/`Upgrade_*`,
`Debug_*` и `Core_DataTransfer*`. Даже diagnostic raw-режим блокирует эти команды.
